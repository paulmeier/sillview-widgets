# Registry index schema

`registry/index.json` is the machine-readable catalog the sillview app consumes to
list and install community widgets. It is generated by `sillview-widgets index` from
the `widgets/` directory and contains only widgets that pass the
[submission gate](submission-guidelines.md).

## Where to fetch it

- **Canonical (source of truth):** the committed file on `main`
  `https://raw.githubusercontent.com/paulmeier/sillview-widgets/main/registry/index.json`
- **CDN mirror (optional):** GitHub Pages
  `https://paulmeier.github.io/sillview-widgets/index.json`

CI enforces (via `index --check`) that the committed file always matches the widgets
in the repo, so the raw endpoint is authoritative.

## Document shape

```jsonc
{
  "schema_version": 1,                       // bump on a breaking format change
  "generated_at": "2026-06-14T00:00:00.000Z",// UTC; informational only
  "repository": "https://github.com/paulmeier/sillview-widgets",
  "widgets": [
    {
      "name": "transactions",
      "version": "1.0.0",
      "description": "The most recent transactions across all accounts.",
      "author": "sillview",
      "license": "MIT",
      "homepage": "https://github.com/paulmeier/sillview-widgets/tree/main/widgets/transactions",
      "kind": "builtin",                     // "builtin" today; "spec" | "bundle" reserved
      "widget_type": "transactions",         // compiled-in sillview type (builtin)
      "category": "Activity",                // Overview | Accounts | Spending | Activity | Market
      "icon": "list",
      "tags": ["transactions", "activity", "ledger"],
      "tier": "verified",                    // verified | community
      "default_size": { "w": 6, "h": 7, "minW": 4, "minH": 4 },
      "config": [
        { "key": "limit", "types": ["number", "string"], "required": false, "description": "…" }
      ],
      "path": "widgets/transactions",        // repo-relative directory
      "files": [
        { "path": "README.md",   "sha256": "…", "size": 492 },
        { "path": "widget.toml", "sha256": "…", "size": 730 }
      ],
      "content_hash": "sha256:…",            // aggregate over all files
      "size_bytes": 1222
    }
  ]
}
```

Widgets are sorted by `name`, and each widget's `files` are sorted by `path`, so the
document is byte-stable across machines (only `generated_at` varies, which the
`--check` comparison ignores).

## Field reference

| Field | Meaning |
| ----- | ------- |
| `schema_version` | Format version. A client should refuse a version it doesn't understand. |
| `generated_at` | When the index was built (UTC). Informational; not part of the integrity contract. |
| `repository` | The registry repository, the base for resolving `path`. |
| `widgets[].kind` | `builtin` (code compiled into the app), or the reserved `spec` / `bundle`. |
| `widgets[].widget_type` | For `builtin`, the compiled-in sillview widget type to render. |
| `widgets[].category` / `icon` / `tags` | Marketplace display + search/filter metadata. |
| `widgets[].default_size` | The tile's initial footprint on sillview's 12-column grid. |
| `widgets[].config` | The authoritative config contract: each key the widget reads and its accepted types. The app validates an instance's config against this. |
| `widgets[].path` | Repo-relative widget directory. Combine with `repository` + a ref to fetch files. |
| `widgets[].files[]` | Every file in the widget: `path` (forward slashes), `sha256` (hex), `size`. |
| `widgets[].content_hash` | `sha256:` + the SHA-256 of `"<path>\0<filehash>\n"` lines in `path` order. Changes if any file's name or content changes — use it to detect updates. |
| `widgets[].tier` | Trust tier. A `builtin` widget is `verified` (first-party code). The marketplace can group/badge by it. |

## How the sillview app uses the index

1. Fetch and parse the index (in the **main** process — the renderer's CSP blocks
   direct network access); check `schema_version`.
2. Present the catalog with search and category/tag filters.
3. On **install**, record the widget as installed locally. For a `builtin` widget no
   files are downloaded — the registry entry only gates which compiled-in
   `widget_type` the user may add.
4. The Add-widget panel offers only installed widgets; adding one places a
   `widget_type` tile on the active dashboard.

> When `bundle` widgets land, the install step will additionally download each file
> in `files[]` from `<repository>/raw/<ref>/<path>/<file>`, verify its `sha256`
> **before** writing it, and recompute `content_hash` as a whole-widget check.
